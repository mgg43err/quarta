# План реализации: лендинг обжарки «Кварта»

Источник ТЗ: https://tz.vitai.world/ (+ PDF-бриф `/kvarta-brief.pdf`). Дедлайн: пн 19.10, 18:00 МСК.

Цель плана: агенты выполняют всё максимально автономно, участие пользователя — только список «Действия пользователя» в конце.

---

## Ключевые решения (принять сразу, чтобы агенты не угадывали)

| Решение | Выбор и почему |
|---|---|
| Стек | **Next.js (App Router) + TypeScript + Tailwind CSS**. Приоритет клиента, задеплоится на Vercel без проблем. |
| Хостинг | **Vercel** (бесплатный, из списка ТЗ). Деплой через `vercel` CLI. |
| Хранение заявок | **SQLite (better-sqlite3), файл в `/tmp/leads.db`** на Vercel. ТЗ явно разрешает файл/SQLite. Ограничение: файл эфемерный (портится при пересоздании инстанса) — честно записать в README + добавить экспорт заявок. |
| Телефон | Белорусский мобильный: нормализация `+375 (25/29/33/44) XXXXXXX`, 9 цифр. Принимать варианты: `+37529...`, `8029...`, `8029-...`, `029...`, `29...` (с ведущей 8/0 или без). Невалидный — понятная подсказка под полем, `/api/lead` возвращает `400` с текстом ошибки. |
| Дедупликация | Тот же нормализованный номер (телефон) в течение 10 минут → вторая заявка **не создаётся**. Сервер возвращает `200` с `"ok": true, "duplicate": true` и текст «Заявка уже принята, мы перезвоним» — чтобы повторная отправка/двойной клик не пугали пользователя. Также блокировать кнопку на клиенте. |
| Источник заявки | Ловим utm_source / utm_medium / utm_campaign / utm_content / utm_term, gclid, yclid, referrer, полный URL. Сохраняем в заявку + показываем менеджеру (в Telegram и при экспорте). Параметры помнить на клиенте (state/sessionStorage), подхватывать в скрытые поля формы. |
| Telegram-бот (бонус) | Делать **последним**, за env-переменной `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`. Нет токена — деградирует молча до лога на сервере, ничего не ломает. |
| Логотип | Текстовый wordmark «Кварта» (type-based, без графики). |
| Язык сайта | Русский (клиент в Минске, аудитория по ТЗ). |

## Структура проекта

```
quarta/
├─ app/
│  ├─ layout.tsx          # метаданные + OG-теги, шрифты
│  ├─ page.tsx            # лендинг, секции ниже
│  ├─ api/lead/route.ts   # POST /api/lead: валидация → дедуп → запись → (tg)
│  └─ og.tsx (или image)  # OG-картинка 1200×630
├─ components/            # секции лендинга, LeadForm, Field, PhoneInput
├─ lib/
│  ├─ phone.ts            # нормализация + валидация BY-номеров (использовать и на клиенте, и на сервере)
│  ├─ utm.ts              # сбор параметров
│  ├─ db.ts               # SQLite: таблица leads (name, phone, interest, comment, utm_*, referrer, source_url, created_at)
│  └─ telegram.ts
├─ public/                # фото, favicon, og-image
├─ data/leads.sqlite      # локально; на Vercel путь к /tmp (конфиг через env: LEADS_DB_PATH)
└─ README.md
```

Контракт `POST /api/lead`:
```jsonc
// request
{ "name": "Анна", "phone": "+375291234567", "interest": "subs|order|question",
  "comment": "...", "utm": { "source": "...", "medium": "...", "campaign": "...", "content": "...", "term": "..." },
  "referrer": "...", "sourceUrl": "..." }
// response 200 (успех или дубль)
{ "ok": true, "duplicate": false }
// response 400/500
{ "ok": false, "error": "Человекочитаемый текст" }
```

## Секции лендинга (порядок и содержание)

Все тексты — на основе брифа, переписать живым тёплым тоном без «премиального глянца»:

1. **Hero + CTA «Оставить заявку»** — «Кофе, который обжарили на этой неделе» / срок свежести 1–3 дня как главный оффер. Форма **не** в hero — CTA-кнопка скроллит к форме.
2. **«Кто мы»** — Аня и Дмитрий, экс-бариста, обжаривают партии по 5 кг с 2019, своя мастерская. Почему свежесть важна: зерно деградирует от воздуха/времени, мешок «супермаркетного» кофе может быть полгода старым.
3. **Ассортимент с ценами** — таблица/карточки ровно по брифу: Эфиопия Иргачеффе 32, Колумбия Уила 29, Бразилия Серрадо 26, дрип-пакеты ×10 — 18, подписка 2×250 г — 54 BYN/мес (доставка бесплатно). Вкусовые ноты давать коротко (ноты + степень обжарки), без пафосных описаний.
4. **Подписка** — отдельный блок: как работает (раз в месяц 2 пачки, бесплатно до двери).
5. **Доставка и самовывоз** — пятничная доставка по Минску, от 50 BYN бесплатно; мастерская: ул. Короля, 9, пн–пт 8–20, сб–вс 10–18.
6. **Форма заявки + контакты** — имя, телефон, интерес (подписка / разовый заказ / вопрос), комментарий. Валидация на клиенте и сервере, статусы после отправки.
7. Футер — короткие контакты, часы.

### Дизайн-гайд (защита от «сгенерированного вида»)

- **Палитра**: тёплая бумага (#F3EEE6 / #FAF6EF), глубокий шоколад (#2C1F14 / #3B2A18), один акцент — бордо/терракота/copper (#8B3A28 или #A0522D). Никаких градиентов из фиолет в блю.
- **Типографика**: пара шрифтов с характером, а не Inter/Roboto. Дисплейный — что-то с кириллицей: «Prata» или «Lora» для заголовков + «Manrope» для текста. Крупные заголовки, ограниченная ширина строк, много воздуха.
- **Неравномерная композиция**: широкие hero-фото, таблица цен как настоящая таблица (не 3 карточки в ряд), факты оформлены как редакционный текст (подписи, врезки), цифры «01/02/03» — деликатные, не гигантские заглушки.
- **Фото**: 2–4 реальных фото обжарки/кофе с Unsplash/Pexels (тёмные тёплые кадры, руки, оборудование), без стоковых улыбок и пентхаусов. Проверять лицензию в README.
- **Микродетали**: hover-состояния на всех кликабельных, мелкая техническая типографика (моно шрифт для меток вроде «свежесть: 1–3 дня»), акцентная линия сетки.

## Этапы работ (по очереди агентам, каждый этап = свой коммит)

### Этап 0 — инициализация
- Создать Next.js-приложение (`npx create-next-app@latest` — TS, Tailwind, App Router), Git init, первый коммит.
- Установить `better-sqlite3`. Проверить, что `npm run dev` стартует без ошибок + `npm run build` проходит.
- Коммит: `chore: scaffold next.js app`.

### Этап 1 — контент и дизайн лендинга
- Реализовать все 7 секций + тексты по гайду выше. Мобильная-first вёрстка.
- Фото уложить в `/public`, favicon.
- Коммит: `feat: landing sections`.

### Этап 2 — форма и API
- `LeadForm` + `PhoneInput` (маска `+375 (29) 123-45-67`), переключатель интереса, textarea.
- Валидация имени (не пусто, минимум 2 символа) и телефона в `lib/phone.ts` (один и тот же модуль на клиенте и сервере).
- `POST /api/lead`: валидация → дедуп (10 мин) → запись в SQLite → ответ.
- Понятные состояния: отправка (кнопка disabled + спиннер), успех («Заявка принята, перезвоним»), ошибка сети («Не отправилось — попробуйте ещё раз, не получается — позвоните нам»), ошибка валидации под полем.
- UTM-захват по всей цепочке.
- Автотесты на `lib/phone.ts` (vitest): наборы номеров форматов + валидные/невалидные. Коммит: `feat: lead form + api`.

### Этап 3 — бонусы и полировка
- OG-теги (title, description, og:image) + OG-картинка 1200×630 (`ImageResponse` из Next или статичный файл).
- Умеренные анимации: плавный скролл к форме, hover, лёгкий fade-in секций. Без JS-библиотек анимаций — CSS и `IntersectionObserver`.
- Telegram: `lib/telegram.ts` → текст заявки менеджеру (имя, телефон, интерес, комментарий, UTM-строка). Env-driven, без токена — мягко отключён, ничего не ломает.
- Коммит: `feat: og tags, animations, telegram (optional)`.

### Этап 4 — деплой и проверка
- `npm run build` локально, сборка без ошибок.
- Деплой `vercel --prod`. Прогнать форму на проде через Browser MCP: реальная заявка с UTM-параметрами, повторная отправка (принципиально дедуп), невалидный номер, пустое имя.
- **Lighthouse mobile**: через `npx lighthouse <url> --only-categories=performance,accessibility --form-factor=mobile --chrome-flags=\"--headless\"` или DevTools. Скриншот/отчёт сохранить. Целевые: ≥ 90 performance / ≥ 90 accessibility.
- Коммит: `chore: deploy config`.

### Этап 5 — README и финальные артефакты
README (~полстраницы, по ТЗ):
- что делал агент / что пользователь; где ИИ ошибся и как это заметили (в процессе работы фиксировать реальные ошибки!);
- почему SQLite-файл и ограничение `/tmp` на Vercel; как выгрузить заявки — CSV-эндпоинт `GET /api/leads/export`, защищённый токеном через env `EXPORT_TOKEN`;
- допущения (например, только мобильные префиксы 25/29/33/44);
- что не успели / сделали бы иначе.

- История коммитов — по этапам, осмысленные сообщения (требование ТЗ: коммиты по шагам, а не один).
- Экспорт сессии: пользователь в конце запустит `/export` (или скриншоты ключевых моментов). Не причёсывать.
- Коммит: `docs: readme`.

## Действия пользователя (постараться один блок в конце)

Этапы 0–3 агенты делают полностью сами, без юзера. Пользователь нужен только один раз в конце для:
1. **Залогиниться в Vercel**: агент запустит `vercel login` → юзер один раз подтверждает в браузере. Дальше деплой делает агент.
2. **Пуш в GitHub**: агент проверяет `gh auth`; если токена нет — пользователь разово проходит `gh auth login` (дальше агент пушит сам).
3. **(Опционально) Telegram-бот**: если нужен бонус — создать бота в @BotFather и передать агенту токен; иначе пропускаем.
4. **Отправить работы** тому, кто прислал задание: ссылка на сайт + ссылка на репо + экспорт сессии + Lighthouse + README.

Все правки по дизайну/текстам собирать пакетно — пачкой, не по одному замечанию.

- [ ] OG-превью тянется (проверить через https://www.opengraph.xyz/ или opengraph.io).
- [ ] В README нет выдуманных фактов — только то, что есть в брифе или явно допущено.
- [ ] Коммиты соответствуют этапам.
